Before you start 30 min ahead

  • Run demo\reset-demo.bat (about a minute). It rebuilds both demo libraries so everything is exactly as in this script.
  • Start demo\start-demo-live.bat (empty library, port 8765) and demo\start-demo-ready.bat (everything already processed, port 8766). Your browser opens on the live one; open the ready one in a second tab from the address in its window. The second is your safety net.
  • Open demo\evidence\results-at-a-glance.html in a third tab.
  • Open demo\alt-text-drafts.txt in Notepad, ready to copy from. Read the drafts against the images once: you stand behind them.
  • File Explorer open at the samples folder, so you can find it quickly in the folder picker.
  • Browser zoom to about 125 % (Ctrl + +) so the back of the room can read it. Close other tabs and mute notifications (Windows: Focus assist).
  • In Teams, share the browser window, not the whole screen. Test the sound and that the room can see the text.
  • Optional: record a full run-through (Teams recording or Win + Alt + R) as a video you can play if everything fails.

1. Why, and the numbers 0:00 – 2:30

Opening
DoSay
Start on the results at a glance tab. “We publish a lot of PDFs and we have to make them accessible. Today that means sending them to a bureau, which is slow and expensive, and in practice it doesn’t always happen. So a backlog builds up and then arrives as one big invoice.”
Point at the four big numbers: 10 publications, 386 pages, 12,956 → 136 failed checks, 4 of 10 pass completely. “I built a tool that does the structural work automatically. These are our own published reports. Before: nearly 13,000 failed checks in the standard PDF/UA check. After the tool, 136. Four pass completely with no human work at all.”
Scroll the table. Pause on Beretning (3,367 → 43) and Menneskerettigheder … menneskehandelsområdet (1,617 → passes). “What’s left is almost entirely image descriptions: 130 of the 136. That’s deliberate. Only a person who knows the publication can say what an image is for.”
Say who checks. “The check is done by veraPDF, an independent open-source validator, not by my own code. And everything runs on this computer: nothing is uploaded anywhere.”

Processing live
DoSay
Switch to the live tab (empty Library). Under Add PDFs, use Or add a whole folder and choose the samples folder. Confirm the browser’s “upload” question. “Here is the library, empty. I’ll add a whole folder of our publications: Word and InDesign, Danish, English and Spanish.”

Some were already tagged, others, the InDesign exports, had no structure at all and the tool built it. Ten publications, 386 pages.”

If it is slow or stalls: keep talking over the numbers page, or switch to the ready tab (port 8766) and say “I processed these earlier”. See if something goes wrong.

4. The human part: image descriptions 8:00 – 11:00

Writing two image descriptions live
DoSay
Library → open Børns oplevelser med vold … (10 pages). Images tab: two images, both charts. “This is the part only a person can do. The tool finds every image, shows it large, shows where it sits on the page and the text near it.”
Click into the box. Paste the first draft from alt-text-drafts.txt (page 4). Press Ctrl + Enter. The first save can pause a few seconds. “I describe what matters: the chart type, the groups and the numbers. Ctrl+Enter saves and moves to the next image. For a chart, the point is the finding, not the colours.”
Second image: paste the page 6 draft, Ctrl + Enter. Note the tab now reads Images ✓. “Two images, a minute of work. If an image is purely decoration, one button marks it Decorative and screen readers skip it.”
Document tab: the tool guessed the title from page 1; check it reads right and tick the item. “Same here: it guessed the title, I confirm it.”
Click Validate and download accessible PDF. The Result tab shows ✓ Passes the automated PDF/UA-1 check (veraPDF). “Now it passes. The tool only adds the PDF/UA stamp once the validator agrees: it never claims something it can’t back up.”
Why this one: two images means it finishes live, and the Danish charts show that descriptions need real judgement. Don’t do the Colombia queue live (8 photos); just show it exists.

5. The tag editor 11:00 – 14:00

When the automatic result needs a human touch
DoSay
Open 26.06.18 Policy Brief Colombia - DIGITAL.pdf → Pages tab → page 15 (a three-column table). Click Fit width. “Sometimes the automatic result needs a human eye. This is the tag editor: the page on the right, every block numbered in the order a screen reader will read it, and the structure on the left.”
Click a table cell in the list. In Selected block change Cell type to Header for its column. Then press Ctrl + Z. “Every edit can be undone. I can change a block’s type, move it earlier or later, merge blocks, mark something as decoration, or fix table headers.”
Click a text block, then press Alt + ↓ to move it down; press Ctrl + Z. Mention the arrow keys in the list. “It works with the keyboard, too. An accessibility tool has to be accessible, so I tested the interface itself with an automated checker.”
Be honest about limits: open the Annual Report (86 pages) → Pages → page 36 (an infographic). “This is where it struggles: infographics. The big numbers and their labels aren’t always read in the right order. A person fixes those. That’s what the editor is for.”

7. Honest limits, and what next 16:00 – 18:00

Say this plainly (it is what makes the rest credible):

  • “Passing the validator is strong evidence, not a certificate. It can’t tell if a description is meaningful or the reading order makes sense on a complicated page. A person still looks over every file.”
  • “I tested it on ten publications. That’s a start, not proof.”
  • “Scanned PDFs aren’t handled yet (they’re flagged). Infographics need manual work. It has only been tried in one browser and I haven’t tested it with a screen reader yet. I’d like a colleague who uses one to try it.”

Then the proposal:

  • A pilot: 30 to 50 real documents with a few colleagues, measuring minutes per document against what the bureau costs and how long it takes.
  • Where it lives: today it runs locally on one computer. For a few colleagues in comms it would sit on an internal server with Microsoft sign-in, and that’s a conversation with Aske.
  • Fix it at the source: the reports show exactly what our InDesign and Word templates miss, so improving the templates would cut the human work further.

Likely questions, straight answers

“Is this WCAG-compliant?”

It checks against PDF/UA-1, the PDF accessibility standard that WCAG relies on for documents, using an independent validator. WCAG conformance also needs human judgement (image descriptions, reading order, language), so we call it “passes the automated check”, never “certified”.

“Why not just use Acrobat Pro?”

Acrobat’s checker and manual tagging is exactly the slow work this automates. This tool does the structure in bulk, offline, built around our own InDesign and Word output, and keeps a person for the judgement parts. Acrobat is still fine for spot-checks.

“What about the bureau?”

They remain an option for hard cases or sign-off. The question for management is what assurance we want (a statement, someone accountable) and how much volume can be handled in-house. The pilot gives the numbers to decide.

“Is it secure? GDPR?”

In local mode nothing leaves the computer. A server version would run inside our own infrastructure with sign-in restricted to a group and automatic deletion of old files. We’d agree the details with Aske.

“Who maintains it?”

Be straight: today it’s one person plus an AI assistant that helped write and test it. If we adopt it, it needs a named owner and time set aside. There is documentation, a built-in self-test and a repeatable build, but it’s a real responsibility.

“What does it cost?”

No licences: it’s built on open-source components. The costs are the owner’s time, hosting, and perhaps a code-signing certificate so Windows doesn’t warn on first run.

“Danish and Spanish?”

Yes: it detects Danish, English and Spanish and sets the document language. The tool’s own screens are English only for now.

“Can I try it?”

Not yet. First a pilot with a few people, and agreement from IT on where it runs.

Notes for you (not for the room)

  • Write down reactions. Which part made people lean in? Which questions came up twice? That tells you what the pilot should test.
  • Collect the pilot numbers now. From the bureau’s invoices: price per document or page, typical turnaround, and how many PDFs per year. From the tool: minutes per document. That’s your business case.
  • Questions for Aske: can it run as a small Linux container on the internal server or in Azure? Sign-in through Entra ID limited to a group? How long may unpublished documents be stored? How many CPU cores and how much memory? Who patches and monitors it, and what address and certificate? Is there antivirus scanning for uploads? And: may a no-install folder run on work laptops at all?
  • Don’t promise dates, savings or compliance. Promise a pilot and honest numbers.
  • Ownership: before the department sees this, be sure you know who owns it (your contract, your union’s legal helpline).
